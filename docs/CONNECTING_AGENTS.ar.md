# ربط TapMesh بالإيجنت والمشاريع

[English](CONNECTING_AGENTS.md) · [تثبيت التطبيق](../README.ar.md) · [عقود الأدوات](TOOL_CONTRACTS.md)

يوفّر TapMesh خادم **MCP**. يعدّل الإيجنت كود مشروعك، ثم يستخدم أدوات TapMesh لاكتشاف الأجهزة وبناء تطبيق iOS وتثبيته وتشغيله وقراءة الشاشة والتفاعل معها. لا تحتاج إلى إضافة SDK داخل تطبيق الجوال. المهارة أو ملف تعليمات المشروع ينظّم خطوات العمل؛ لا يستبدل اتصال MCP ولا يمنح صلاحية التحكم بالجهاز.

يشرح هذا الدليل مصدر Developer Preview ‏0.2.0. راجع [حالة الإصدار](RELEASE_STATUS.md) عند اختيار الحزمة. نشر المصدر لا يعني اجتياز الحزمة بوابات الإصدار أو نشرها للعامة.

## 1. الربط مع برنامج الإيجنت

من TapMesh افتح **الإعدادات › عملاء الذكاء الاصطناعي**، أو **مساعدة › ربط عميل ذكاء اصطناعي…**. انسخ الإعداد الذي يولّده التطبيق لمسار تثبيته الفعلي. للنسخ الأقدم التي لا تحتوي هذه الشاشة، استخدم الإعداد اليدوي التالي.

في العملاء الذين يستخدمون صيغة `mcpServers`:

```json
{
  "mcpServers": {
    "tapmesh": {
      "command": "/Applications/TapMesh.app/Contents/MacOS/tapmesh-mcp"
    }
  }
}
```

نوع الاتصال **stdio**. هذا إعداد لبرنامج الإيجنت، ولا يُضاف إلى كود تطبيق iOS. إذا كان العميل يستخدم صيغة أخرى، أدخل الأمر في إعداد خادم stdio لديه. عدّل المسار المطلق إذا كان التطبيق في مجلد آخر؛ لا تتحول `~` تلقائيًا داخل JSON. زر النسخ في TapMesh يضع المسار الصحيح. يوجد [ملف مثال جاهز](../examples/mcp/tapmesh.json).

لـClaude Code، نفّذ الأمر داخل مجلد المشروع ليكون نطاقه المحلي الافتراضي، أو انسخ الأمر من TapMesh:

```sh
claude mcp add tapmesh -- '/Applications/TapMesh.app/Contents/MacOS/tapmesh-mcp'
```

لإتاحته عبر مشاريعك، استخدم نطاق المستخدم:

```sh
claude mcp add --scope user tapmesh -- '/Applications/TapMesh.app/Contents/MacOS/tapmesh-mcp'
```

أعد تحميل اتصال MCP في العميل. يفترض أن يكتشف الأدوات الخمسين، ومنها `list_devices` و`select_device` و`take_screenshot` و`build_and_run`. يقرأ المشغّل الاتصال المحلي ويبدأ TapMesh عند عدم جاهزية خدماته. أبقِ التطبيق يعمل أثناء الاستخدام؛ إغلاق النافذة يترك الخدمات متاحة، وإنهاء التطبيق يوقف خدماته المملوكة له.

لا تنسخ ملفات الاتصال أو المفاتيح أو بيانات الموافقات إلى إعداد MCP أو تعليمات المشروع أو Git. لا تحتاج إلى بورت ثابت أو حساب سحابي. يعمل المشغّل وخدمات TapMesh وXcode واتصال الجهاز على Mac؛ المسار المحلي وحده لا يربط بيئة سحابية بعيدة بجهازك. يحتاج العميل البعيد إلى آلية تشغيل MCP على Mac يدعمها هو.

## 2. تعريف المشروع للإيجنت

للبناء المباشر من Xcode، أعطه:

- المسار الكامل لملف `.xcworkspace` أو مجلد `.xcodeproj`، وليس مجلد المشروع الأب فقط.
- اسم الـScheme المشترك وإعداد البناء، مثل `Debug`.
- Bundle ID، مثل `com.example.myapp`.
- الجهاز الذي تسمح له باستخدامه، ونتيجة مرئية للتحقق من نجاح التشغيل.

يجب تجهيز Xcode وتوقيع المشروع وملفاته اللازمة للجهاز الحقيقي. جهّز مجلد iOS المولّد ومتطلبات إطار العمل بأدوات المشروع المعتادة أولًا. تستدعي `build_and_run` أمر `xcodebuild`؛ لا تحوّل مشروع ويب أو خادم إلى تطبيق iOS، ولا تشغّل خوادم التطوير الخاصة بالأطر تلقائيًا.

يمكن حفظ هذه البيانات في ملف تعليمات يقرأه الإيجنت، مثل `AGENTS.md`. يوجد [قالب تعليمات مشروع](../examples/mcp/project-instructions.md) لتعديله ونسخه إلى الملف المناسب لعميلك. القالب ليس مهارة مثبتة.

## 3. السماح بمجلد البناء

من **الإعدادات › مجلدات البناء** اسمح بالمجلد الذي يحتوي مشروع Xcode أو الـworkspace. اتبع طلب إعادة تشغيل الخدمات إن ظهر لتطبيق الأذونات الجديدة. السماح بالمجلد لا يوافق على كل بناء؛ يظل `build_and_run` بحاجة إلى موافقة تنفيذ على Mac من داخل TapMesh.

لا يستطيع الإيجنت الموافقة على طلباته. تقرر أنت السماح بالتحكم العادي على جهاز حقيقي جديد. تبقى العمليات الحساسة والحذف والبناء والخطوات المحمية خاضعة لموافقاتها أو لتدخلك. استخدم **إيقاف** و**استئناف** من TapMesh عند الحاجة.

## 4. البناء والتشغيل والتحقق

يعمل الإيجنت بالتسلسل التالي:

1. يستدعي `list_devices`، ويفحص الجاهزية والقدرات، ثم `select_device` للجهاز المطلوب داخل جلسته.
2. يستدعي `build_and_run` مع `project_path` و`scheme` و`configuration` و`launch: true`. توافق أنت على طلب البناء من TapMesh.
3. يفحص نتائج مراحل البناء والتثبيت والتشغيل. إذا كان التطبيق مبنيًا بالفعل، يستخدم `install_app` و`launch_app` مع الموافقات اللازمة.
4. يستدعي `get_foreground_app` و`take_screenshot` و`list_elements` عند دعمها للتحقق من التطبيق والشاشة المتوقعة.
5. يقرأ الشاشة الحالية قبل الإدخال، ويتحقق من النتيجة بعده. وصول أمر التحكم لا يثبت نجاح العملية داخل التطبيق، ولا يُعاد أمر غير مؤكد بصورة عمياء.

مثال طلب:

> استخدم TapMesh MCP لهذا المشروع. المسار `/path/MyApp/MyApp.xcworkspace`، والـScheme هو `MyApp`، والـBundle ID هو `com.example.myapp`. اعرض الأجهزة واختر الآيفون الذي أسمح لك به. ابنِ التطبيق وشغّله، ثم تحقق من ظهور الصفحة الرئيسية. توقّف للموافقات المطلوبة ولا تتعامل مع تطبيقات غير مرتبطة بالمشروع.

## أين تظهر شاشة الجوال؟

اختر الجهاز نفسه من الشريط الجانبي في TapMesh لمشاهدة المعاينة. اختيار الجهاز في واجهة Mac مستقل عن اختيار كل عميل MCP؛ اختيارك لا يختار الجهاز تلقائيًا للإيجنت، واختيار الإيجنت لا يغيّر اختيار الواجهة.

تعيد `take_screenshot` صورة MCP وبيانات الملاحظة. ظهور الصورة داخل محادثة الإيجنت يعتمد على دعم العميل للصور. إضافة MCP لا تنشئ تلقائيًا لوحة جوال في كل محرر. يوفّر TapMesh معاينته الخاصة، مع الفيديو عبر USB واللقطات البديلة بحسب [قدرات النسخة والجهاز](../README.ar.md).

## حل المشكلات

- **المشغّل غير موجود:** ثبّت حزمة `.app` كاملة وانسخ مسارها الفعلي؛ مجلد المصدر وحده ليس المشغّل المثبّت.
- **الأدوات لا تظهر:** أعد تحميل اتصال MCP واقرأ رسالة الخطأ في العميل.
- **لا يوجد جهاز مختار:** استخدم `list_devices` ثم `select_device` داخل جلسة الإيجنت وافحص أسباب عدم الجاهزية.
- **الجهاز يحتاج إعدادًا:** افتح القفل بنفسك وفعّل الثقة ونمط المطوّر عند طلبهما. أدخل رمز القفل على الجهاز مباشرة.
- **رفض مجلد البناء:** اسمح بالمجلد من الإعدادات، وطبّق إعادة التشغيل المطلوبة، ثم وافق على طلب البناء المحدد.
- **الصورة لا تظهر داخل العميل:** استخدم معاينة TapMesh وتحقق من دعم العميل لصور MCP. وجود الأداة لا يعني دعم كل جهاز لجميع قدراتها.
